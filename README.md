A small command line URL shortener written in Python, backed by MongoDB.

## What it does

- `--minify` takes a full URL and returns a short URL (e.g. `https://myur.ly/AzlUpL`).
- `--expand` takes a short URL and returns the original URL.

Short URLs expire after a configurable number of seconds:

- Minifying a URL that already has a valid short URL returns the same short URL. Optionally, it also renews the expiration (see `renew_expiration_on_new_minify` in [`cli/config.json`](#cliconfigjson)).
- Once a short URL has expired, `--expand` no longer resolves it. Minifying the original URL again creates a new short URL.

Short codes are random strings of letters and digits, generated by the tool itself without an external library. Uniqueness is enforced by MongoDB unique indexes, and expired entries are removed automatically by a TTL index.

The tool only stores and resolves the mapping. It does not serve HTTP redirects. Input URLs are validated with the [`validators`](https://pypi.org/project/validators/) library and must be `http` or `https`, with a domain name or an IP address as host.

## Installation

Requirements: Docker with Docker Compose, and Python 3.10+ (not needed if you run the CLI in Docker).

### Database

```bash
cd database
cp .env.example .env        # then edit the values, see "Setup" below
docker compose up -d
```

On first start, `mongo-init.js` creates the database, the collection with its validator and indexes, and the application user. It only runs on an empty volume, so later changes to the database configuration need a manual migration or a fresh database. To recreate it from scratch:

```bash
docker compose down -v
docker compose up -d
```

### CLI

With `venv`:

```bash
cd cli
python3 -m venv .venv
source .venv/bin/activate
pip install .
cp config.json.example config.json   # then edit, see "Setup" below
```

With Docker (alternative to `venv`, no local Python needed):

```bash
cd cli
cp config.json.example config.json   # then edit, see "Setup" below
docker build -t myurly .
```

## Setup

### `database/.env`

Used by Docker Compose to configure MongoDB.

- `MONGO_HOST`, `MONGO_PORT`: host interface and port where MongoDB is exposed.
- `MONGO_DATABASE_NAME`: database used by the application.
- `MONGO_COLLECTION_NAME`: collection that stores the URLs.
- `MONGO_ROOT_USERNAME`, `MONGO_ROOT_PASSWORD`: MongoDB admin account.
- `MONGO_APP_USERNAME`, `MONGO_APP_PASSWORD`: account used by the CLI (`readWrite` on the application database).

### `cli/config.json`

Validated against `myurly/config.schema.json` at startup. The `database` values must match `database/.env`, otherwise the tool will not work.

- `database`
  - `host`, `port`: MongoDB address (`MONGO_HOST`, `MONGO_PORT`). `host` is a hostname or IP address, without scheme or port.
  - `username`, `password`: application account (`MONGO_APP_USERNAME`, `MONGO_APP_PASSWORD`).
  - `database_name`: name of the database (`MONGO_DATABASE_NAME`).
  - `collection_name`: name of the collection (`MONGO_COLLECTION_NAME`).
- `app`
  - `db_timeout_seconds`: timeout for every database operation; `0` means no timeout.
  - `short_url_domain`: domain of the short URLs, without scheme, port or slashes (e.g. `myur.ly`).
  - `short_url_length`: length of the random code (minimum 4).
  - `short_url_expiration_seconds`: lifetime of a short URL.
  - `max_generation_attempts`: retries when a generated code already exists.
  - `renew_expiration_on_new_minify`: if `true`, minifying an already shortened URL resets its expiration.

## Usage

```
$ myurly --help
usage: myurly [-h] [--config CONFIG] [--debug] [--debug-db] (--minify MINIFY | --expand EXPAND)

myur.ly - A simple URL shortener

options:
  -h, --help       show this help message and exit
  --config CONFIG  path to the configuration file (default: ./config.json)
  --debug          enable debug mode
  --debug-db       enable debug mode for pymongo, only effective if --debug is also set
  --minify MINIFY  URL to minify
  --expand EXPAND  URL to expand
```

The result goes to stdout; messages and errors go to stderr.

Examples:

```bash
$ myurly --minify=https://www.example.com/path?q=search
https://myur.ly/AzlUpL

$ myurly --minify=https://www.example.com/path?q=search    # same URL, not expired yet
https://myur.ly/AzlUpL

$ myurly --expand=https://myur.ly/AzlUpL
https://www.example.com/path?q=search

$ myurly --expand=https://myur.ly/AzlUpL                    # after expiration
[ERROR] Shortened URL not found or expired.
```

Exit codes:

- `0`: success.
- `1`: short URL not found or expired.
- `2`: invalid command line arguments.
- `3`: generic error.

### With python virtual environment

With the virtual environment active, `myurly` can be run from any directory. The default `--config ./config.json` is relative to the current directory, so from elsewhere pass `--config /path/to/config.json`.

### With Docker

Run from the `cli` directory. `config.json` is mounted into the container. The container has its own network by default; `--network host` makes it use the host's, which it needs for example to reach a database exposed on `127.0.0.1`.

```bash
docker run --rm --network host -v "$PWD/config.json:/app/config.json:ro" myurly --minify=https://www.example.com/path?q=search
docker run --rm --network host -v "$PWD/config.json:/app/config.json:ro" myurly --expand=https://myur.ly/AzlUpL
```

To run it from another directory, change the path of the mounted `config.json`.

## Tests

The tests use `pytest` and run against an in-memory `mongomock` database, so no MongoDB instance is needed.

Run them from the `cli` directory:

```bash
pip install -e ".[dev]"
pytest
```

The tests cover:

- `tests/test_config.py`: loading and schema validation of the configuration file.
- `tests/test_url_handler.py`: minify and expand, idempotency, expiration, code collisions and concurrent inserts.
- `tests/test_main.py`: command line parsing, output and exit codes.
